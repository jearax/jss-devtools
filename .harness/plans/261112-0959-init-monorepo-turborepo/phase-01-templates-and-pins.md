# Phase 1: Templates and pins

## Goal

Every file the monorepo needs exists as a template function, with turbo pinned, and the
single-package templates still produce byte-identical output.

## Context

- Contract and root-file standard: the brainstorm report, sections "Outcome" and "Root files
  follow the Turborepo docs". Layout model: `dokploy/design-system` (decision 0014).
- Proven in a scratch skeleton on pnpm 11.24.0, npm 11.19.1, yarn 1.22.22 and bun 1.3.8: all tooling as root
  devDependencies, the app with no devDependencies, `turbo run build typecheck`, a cached rerun
  and `node apps/node/dist/main.js` all pass.

## Files

- Modify: `scripts/pin-node-preset.mjs` — pin `turbo` into a separate constant, so the
  single-package `devDependencies` do not gain it.
- Modify: `src/commands/init/constants/node-preset-dependency.constant.ts` — regenerated by the
  script, never edited by hand.
- Modify: `src/commands/init/templates/eslint-config-mjs.template.ts` — optional monorepo source
  folders; default output unchanged.
- Modify: `src/commands/init/templates/tsconfig-json.template.ts` — share compiler options with
  the base template; output unchanged.
- Modify: `src/commands/init/templates/pnpm-workspace-yaml.template.ts` — a monorepo variant with
  the `packages` globs.
- Create, one template per file: `turbo-json.template.ts`, `monorepo-package-json.template.ts`
  (root), `app-package-json.template.ts` (`apps/<framework>`), `tsconfig-base-json.template.ts`,
  `app-tsconfig-json.template.ts`.
- Create: `tests/monorepo-templates.test.ts`.

## Steps

1. **turbo pin.** Add `turbo` to the pin script so it writes a second exported constant (for
   example `MONOREPO_PRESET_DEPENDENCIES = { turbo: '<x.y.z>' }`), then run the script. The pin
   must be older than `minimumReleaseAge` (1440 minutes): turbo 2.11.11 was under a day old on
   2026-11-12, and 2.11.10 is the version the skeleton proved. Do not edit the constant by hand.
2. **`turbo.json`**, exactly:
   `$schema` `https://turborepo.dev/schema.json`; `build` with `dependsOn: ["^build"]` and
   `outputs: ["dist/**"]`; `typecheck` and `lint` with `dependsOn: ["^build"]`; `dev` with
   `cache: false` and `persistent: true`; `"//#lint:root": {}`. No `test` task (validation
   session 1). <!-- Updated: Validation Session 1 - no test task -->
3. **Root `package.json`**: `name` from `derivePackageName`, `version` `0.0.0`, `private`,
   `type: module`, `engines.node`, top-level `packageManager`, and for npm, yarn and bun
   `workspaces: ["apps/*", "packages/*"]`. Scripts: `build`, `dev`, `typecheck` as
   `turbo run <task>`; `lint` as `turbo run lint lint:root`; `lint:root` runs ESLint on the root's
   own `*.{cjs,mjs,js,jsx,cts,mts,ts,tsx}`; `lint:fix` runs `eslint --fix` over the root and
   `{apps,packages}/*` sources; `format` as `<run> lint:fix && prettier --write .`;
   `prepare: husky`. `lint-staged` keys extend the single-package ones with
   `apps/*/` and `packages/*/` source folders, and use `**/package.json` for the sort, as
   design-system does. `devDependencies`: every `NODE_PRESET_DEPENDENCIES` entry plus turbo, as
   caret ranges like the single-package template.
4. **App `package.json`** at `apps/<framework>`: `name` `@<root-name>/<framework>`,
   `version` `0.0.0` (yarn 1 ignores a workspace without one), `private`, `type: module`, scripts
   `dev` (`tsx watch src/main.ts`), `build` (`tsc && tsc-alias --resolve-full-paths`), `start`,
   `typecheck` (`tsc --noEmit`), `lint` (`eslint src`). No `devDependencies`.
5. **TypeScript.** `tsconfig.base.json` holds the compiler options the single-package
   `tsconfig.json` has today, minus `paths`, `rootDir` and `outDir`. The app's `tsconfig.json`
   extends `../../tsconfig.base.json` and adds `paths: {"@/*": ["./src/*"]}`, `rootDir`, `outDir`
   and `include: ["src"]`. Refactor `tsconfig-json.template.ts` to build from the same options
   object so its output stays byte-identical. No root `tsconfig.json` (Turborepo TypeScript guide).
6. **ESLint.** Let the template take an optional monorepo switch that adds
   `apps/*/{src,test,tools,e2e}` and `packages/*/{src,test,tools}` to `SOURCE_FOLDERS`, as
   design-system's config does. Globs in a flat config resolve from the config's folder, so the
   single-package globs alone never match `apps/node/src`. With the switch off, the output must
   equal today's byte for byte, because existing mode compares owned files by exact content.
7. **pnpm workspace.** A monorepo variant: `packages:` with `apps/*` and `packages/*` (no `**`
   globs; the docs say they are unsupported), then today's `allowBuilds`, `strictPeerDependencies`
   and `engineStrict` block.
8. **Tests** in `tests/monorepo-templates.test.ts`: assert the exact parsed shape of `turbo.json`,
   the root and app `package.json` per manager (workspaces present for npm, yarn and bun, absent
   for pnpm), both tsconfigs, and the pnpm workspace file. Add a test that the single-package
   templates' output is unchanged (snapshot of the current strings or a comparison against the
   committed expectations in `tests/node-preset-templates.test.ts`).

## Verification

- `pnpm test -- tests/monorepo-templates.test.ts tests/node-preset-templates.test.ts`
- `git diff --stat src/commands/init/constants/` shows only the new turbo constant.
- `pnpm lint && pnpm typecheck`

## Risks

- The tsconfig and ESLint refactors can change a byte of single-package output; the unchanged
  tests are the guard, and their expectations must not be edited.
