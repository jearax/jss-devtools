# 0047: init --framework nest copies the ESM Nest 12 app kept in templates/nest/

## Context

[0030](./0030-init-node-preset.md) builds only `node`. The user wants a Nest preset built on Nest's
modules and DI, not a copy of their full reference template. Contract and evidence: the
[brainstorm report](../plans/reports/brainstorm-261112-1953-init-nest-preset.md).

## Decision

`init <dir> --framework nest` and `init <dir> --monorepo --framework nest` (app at `apps/nest`)
create a Nest 12 app; existing mode with `nest` exits 1 before any write. The Nest files live as a
real project in `templates/nest/` at the repository root: the pinned `nest new` output, edited.
The build embeds it in the bundle and init copies it; init never runs `nest new`. Toolchain files
shared with the `node` preset stay generated by the existing templates, so each has one home. The app
is ESM: `@/` imports carry `.js`, so its ESLint requires the extension the `node` preset forbids.
Nest's vitest stays, oxlint gives way to the ESLint preset, and Nest's `AGENTS.md` is not kept.
`src/` holds `main.ts`, `app/`, `core/{config,logger,i18n,database,helper}` and `domains/`. zod
validates the env and the requests through Nest 12's Standard Schema support, and
`@nestjs/i18n` translates the issues per request. `database` and `helper` are `@Global()` modules
with one small working provider each; no ORM.

> "Không phải scaffold full như repo refs đâu nha, đại loại là base-on concept `modular`, DI …"

> "ESM + @/ có đuôi .js" · "Giữ vitest của Nest" · "Thay bằng ESLint preset" · "Không ORM, chỉ khung"

> "zod, dịch theo request, cho thêm core/i18n đi" · "@nestjs/i18n" · AGENTS.md: "Xóa hẳn"

> Generation: "Template trong code" · Modes: "Create + --monorepo" (user, 2026-11-12)

> "Giống --monorepo nhưng sẽ có kiểu wraper folder lại để làm template của riêng nha. Ví dụ
> template/nest/ … sau khi nest init + update các file" · location: "templates/nest/ ở root"

## Consequences

- The ESLint and tsconfig templates vary by framework; the `node` preset's output is unchanged.
- Nest versions move through `scripts/pin-node-preset.mjs`, like every other pin.
- `@nestjs/i18n` is 0.x: a release can change its API, so the pin moves only with the e2e green.
